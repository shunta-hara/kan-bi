# UI ポリッシュ 仕様書

## 概要

既存のダッシュボード・データソース管理画面に存在する視覚的バグと細部の品質不足を解消する。
対象は「モーダルの表示位置ずれ」「ダークモードでのコントラスト不足」「フォーム・ボタン・テーブルの細かな未整備」の3領域で、既存機能の削除・再設計は一切行わない。
利用者はすべての操作画面で一貫性のある、目に優しい UI を体験できるようになる。

---

## 機能一覧

### FEAT-UI-001: モーダル水平・垂直センタリング

- **優先度**: Must
- **説明**: ダッシュボード新規作成・ウィジェット追加・ウィジェット設定編集の各モーダルが、画面サイズやスクロール位置に関わらず常にビューポートの中央（水平・垂直）に表示される。現状はネイティブ `<dialog>` 要素に `margin: auto` 相当の指定が欠けており、ブラウザ環境によって上寄りになる。
- **受け入れ基準**:
  - [ ] `CreateDashboardDialog`・`AddWidgetDialog`・`WidgetEditDialog` の3ダイアログを開いたとき、モーダルのボックスがビューポートの水平方向中央に表示される
  - [ ] 同3ダイアログが垂直方向についてもビューポート中央に表示される（画面をスクロールしていない状態・スクロールした状態いずれでも）
  - [ ] バックドロップ（半透明のオーバーレイ）がモーダルの背後に全画面で表示される
  - [ ] モーダル内コンテンツがビューポート高さを超える場合、モーダル自体がスクロール可能になる（コンテンツが切れない）

### FEAT-UI-002: ダークモードテキストコントラスト改善

- **優先度**: Must
- **説明**: ダークモード時に `white/40`（40% 不透明度）や `white/50` 相当の薄さで描画されているテキストを、WCAG AA 基準（コントラスト比 4.5:1 以上）を満たす濃度に引き上げる。主な対象は、ダッシュボードカードのメタ情報（ウィジェット数・更新日時）、ウィジェット設定ダイアログのプレビューパネルのラベル、フィルター/ソートの空状態メッセージ、データソースカードの定義リストの `dt` 要素、データプレビューテーブルの補足テキスト。
- **受け入れ基準**:
  - [ ] ダークモードで、ダッシュボードカードのメタ情報（ウィジェット数・更新日時）が `dark:text-white/60` 以上の濃度で表示される
  - [ ] ウィジェット設定ダイアログのプレビューパネル内の各ラベルが `dark:text-white/60` 以上の濃度で表示される
  - [ ] フィルター/ソートの「未設定」旨の空状態メッセージが `dark:text-white/55` 以上の濃度で表示される
  - [ ] データソースカードの定義リスト（スプレッドシート ID・範囲・認証方式・更新間隔・更新日時の各ラベル）が `dark:text-white/60` 以上の濃度で表示される
  - [ ] プレビューテーブルの「表示を一部省略している」旨の補足テキストが `dark:text-white/55` 以上の濃度で表示される
  - [ ] ライトモードでは既存のスタイルから変化がない（ライトモード側の色値を変更しない）

### FEAT-UI-003: フォームのプレースホルダー色統一

- **優先度**: Must
- **説明**: ライト・ダーク両モードで、テキスト入力・テキストエリアのプレースホルダー文字色がブラウザ依存のデフォルト値から離れ、デザインに沿った一定の濃度で表示される。対象は全入力フォーム（データソース登録フォーム・ダッシュボード作成ダイアログ・ウィジェット追加ダイアログ・ウィジェット設定編集ダイアログ）の `input[type=text]` と `textarea`。
- **受け入れ基準**:
  - [ ] ライトモードで、すべての対象入力欄のプレースホルダーが `text-black/35` 相当の薄さで表示される
  - [ ] ダークモードで、すべての対象入力欄のプレースホルダーが `dark:text-white/35` 相当の薄さで表示される
  - [ ] プレースホルダーの濃度が、通常のテキスト入力値よりも明らかに薄く表示される（混同されない）
  - [ ] ウィジェット設定編集ダイアログ内のインライン入力（フィルター行・ソート行のテキスト欄）も同じ濃度で統一される

### FEAT-UI-004: プライマリボタンのホバー状態追加

- **優先度**: Should
- **説明**: `bg-foreground` を背景に使ったプライマリボタン（「新規作成」「保存」「登録」「PDF ダウンロード」等）が、現状ホバー時の視覚的変化を持たないため、インタラクション可能であることが伝わりにくい。ホバー時に背景色が微妙に変化するフィードバックを追加する。
- **受け入れ基準**:
  - [ ] ライトモードで、プライマリボタンにマウスを重ねると背景色が `#383838` 程度に暗くなる
  - [ ] ダークモードで、プライマリボタンにマウスを重ねると背景色が `#ccc` 程度に明るくなる
  - [ ] `disabled` 状態のボタンにはホバースタイルが適用されない（`disabled:cursor-not-allowed` が維持される）
  - [ ] `transition-colors` によって色変化が滑らかに（瞬変でなく）行われる
  - [ ] 対象ボタン: `DashboardListClient`・`CreateDashboardDialog`・`AddWidgetDialog`・`WidgetEditDialog`・`RegisterDataSourceForm` それぞれのプライマリ送信ボタン

### FEAT-UI-005: データプレビューテーブルの行ストライプ

- **優先度**: Should
- **説明**: `DataSourcePreviewTable` で表示されるデータ行（`<tbody>` の `<tr>`）が単色背景のため、列数・行数が多い場合に目的の行を追うのが難しい。偶数行と奇数行で背景色を交互に変えるゼブラストライプを追加する。
- **受け入れ基準**:
  - [ ] ライトモードで偶数行（2行目・4行目…）の背景が薄いグレー（`bg-black/[.02]` 相当）で表示される
  - [ ] ダークモードで偶数行の背景が薄い白（`dark:bg-white/[.03]` 相当）で表示される
  - [ ] 奇数行は透明背景のまま変わらない
  - [ ] ヘッダー行には既存の `bg-black/[.03]` ストライプが維持され、ゼブラと区別できる

### FEAT-UI-006: ボタン送信中のスピナー表示統一

- **優先度**: Should
- **説明**: フォーム送信中やデータ取得中はボタンのラベルが「送信中...」「プレビュー中...」等のテキストに変わるが、視覚的なスピナーアイコンがなく、処理中かどうかが素早く認識しにくい。ボタンラベルの左にインラインスピナー（`animate-spin` による小さな円）を添えて処理中を明示する。
- **受け入れ基準**:
  - [ ] `CreateDashboardDialog`・`AddWidgetDialog`・`WidgetEditDialog` の送信ボタンが `isPending` 中、ボタン内にスピナーアイコンが表示される
  - [ ] `RegisterDataSourceForm` のプレビューボタンが取得中、ボタン内にスピナーアイコンが表示される
  - [ ] `RegisterDataSourceForm` の登録ボタンが送信中、ボタン内にスピナーアイコンが表示される
  - [ ] スピナーはボタンラベルの左側に配置され、ラベルと 4px 程度の間隔を持つ
  - [ ] スピナーの色はボタンのテキスト色と統一される（白文字ボタンなら白、黒文字ボタンなら黒系）

### FEAT-UI-007: ダッシュボードカードのホバー強調

- **優先度**: Could
- **説明**: ダッシュボード一覧の各カードが現状ホバー時に視覚変化がなく、クリック可能な要素（編集ボタン）の存在感が弱い。カード全体をホバーした際に、枠線かシャドウを微妙に強調することで、ユーザーに「操作できる行」であることを伝える。
- **受け入れ基準**:
  - [ ] ダッシュボードカードにマウスを重ねると、枠線の不透明度が `black/20 dark:white/25` 程度に増す（現在の `black/10 dark:white/15` より濃くなる）
  - [ ] `transition-colors` による滑らかな変化がある
  - [ ] 削除確認パネルが展開されているカードには、ホバー強調が適用されない（誤クリック防止のため）

### FEAT-UI-008: 空状態プレースホルダーのデザイン統一

- **優先度**: Could
- **説明**: ダッシュボード一覧とデータソース一覧の「まだ何もない」空状態表示が、内部余白・テキスト位置・ボーダースタイルの点でわずかに差異がある。両者を同じサイズ・余白・テキスト構成に統一する。
- **受け入れ基準**:
  - [ ] ダッシュボード一覧の空状態表示とデータソース一覧の空状態表示が、同じ内部パディング（`p-12` 相当）で表示される
  - [ ] どちらの空状態も、見出しと説明文が縦に並ぶ同じレイアウト構成を持つ
  - [ ] ダッシュボードとデータソースの空状態でボーダースタイル（`border-dashed` 有無・色）が統一される

## スプリント計画

### Sprint 1: 視覚バグの解消（センタリング・コントラスト・プレースホルダー）

- **対象機能**: FEAT-UI-001, FEAT-UI-002, FEAT-UI-003
- **完了条件**:
  - [ ] 3種類のモーダルが全ブラウザ（Chrome・Firefox・Safari）でビューポート中央に表示される
  - [ ] ダークモードで低コントラストだった全対象テキストが `dark:text-white/60` 以上に引き上げられている
  - [ ] 全対象 `input[type=text]` と `textarea` のプレースホルダー色が `placeholder:` ユーティリティで明示的に設定されている
  - [ ] ライトモードの表示に意図しない変化がないことを手動確認済み

### Sprint 2: UX ポリッシュ（ホバー・スピナー・ストライプ・空状態）

- **対象機能**: FEAT-UI-004, FEAT-UI-005, FEAT-UI-006, FEAT-UI-007, FEAT-UI-008
- **完了条件**:
  - [ ] 全プライマリボタンにホバー時の背景色変化が確認できる
  - [ ] プレビューテーブルのデータ行にゼブラストライプが表示されている
  - [ ] 送信中・取得中のすべての対象ボタンにスピナーアイコンが表示される
  - [ ] ダッシュボードカードのホバー時に枠線強調が確認できる
  - [ ] ダッシュボード一覧とデータソース一覧の空状態が同じパディングとレイアウトで表示される

## UXフロー

### ユーザーが体験する改善後の流れ

1. **ダッシュボード一覧を開く（ダークモード）**
   - カードのメタ情報（更新日時・ウィジェット数）が以前より読みやすいコントラストで表示される
   - 各カードにマウスを近づけると枠線がわずかに濃くなり「ここが操作できる行」と伝わる

2. **新規ダッシュボードを作成するボタンを押す**
   - モーダルが画面中央に出現する（以前は上寄りになることがあった）
   - フォームのプレースホルダーが適切な薄さで表示されており、入力と混同しない
   - 「作成」ボタンを押すと、ボタン内にスピナーが現れ処理中であることが伝わる
   - ホバー時にボタンの色が微妙に変わる

3. **データソース管理を開く**
   - データソース詳細のラベル（スプレッドシート ID・範囲など）がダークモードでも十分読める濃さで表示される

4. **データソース登録フォームでプレビューを取得する**
   - プレビューテーブルの行にゼブラストライプがあり、列が多くても行を追いやすい
   - 「プレビュー」ボタン押下中にスピナーが表示されて通信中を確認できる

5. **ウィジェットを追加・設定する**
   - モーダルが常に中央表示
   - 右側のライブプレビューパネルのラベルがダークモードでも読める
   - フィルター/ソートが未設定の「なし」表示もコントラスト基準を満たしている

## 非機能要件

- **信頼性**: 既存の機能テストおよびビルドが全て通過する状態を維持する。CSSクラスの変更に伴う意図しないスタイル崩壊がないことを手動確認する
- **セキュリティ**: 変更範囲は表示スタイルのみであり、セキュリティ要件への影響はない
- **パフォーマンス**: Tailwind ユーティリティクラスの追加・変更のみであり、バンドルサイズへの影響は無視できる水準にとどめる
- **アクセシビリティ**: ダークモードのコントラスト改善は WCAG AA（コントラスト比 4.5:1）を基準とする。ライトモードの既存コントラストを悪化させない
- **国際化**: テキスト変更は行わないため i18n への影響はない
