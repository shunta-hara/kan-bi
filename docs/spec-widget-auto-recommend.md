# ウィジェット自動推薦 仕様書

## 概要

`WidgetEditDialog` でデータソースを選択した直後に、列の型情報（number / date / string）と列名からルールベースで最適なチャート種別・グルーピング列・集計列・軸列を推薦し、フォームにプリセットする機能。AI API は使用せず、決定論的なルールテーブルで推薦する。ユーザーはデータソースを選ぶだけでグラフの骨格が自動で埋まり、微調整だけで公開できる状態になることを目指す。推薦を望まないユーザーはボタンを押さずにスキップできる。

---

## 機能一覧

### FEAT-AR-001: `autoRecommend` 純粋関数

- **優先度**: Must
- **説明**: `InferredColumn[]` を受け取り、チャート種別・グルーピング列・集計列・X軸列・Y軸列・推薦根拠テキストを含む推薦結果オブジェクトを返す純粋関数。`src/lib/query/autoRecommend.ts` に集約し、副作用・外部依存をもたない。
- **受け入れ基準**:
  - [ ] 関数が `InferredColumn[]` のみを入力とし、外部 API・DB・ランダム値に依存せず同じ入力に対して常に同じ結果を返す
  - [ ] 推薦結果に `chartType`・`groupByColumn`・`measures`（列名＋集計関数）・`xAxisColumn`・`yAxisColumn`・`rationale`（根拠テキスト）が含まれる
  - [ ] 以下の推薦ルールがすべて正しく動作する（優先度順）:

    | 条件 | 推薦チャート | groupBy / xAxis | yAxis / measure |
    |------|------------|-----------------|-----------------|
    | 列が0件 | `table` | なし | なし |
    | number も date も 0件（文字列のみ） | `table` | なし | なし |
    | number 1件・string 0件・date 0件 | `kpi` | なし | number 列 / sum |
    | number ≥2件・string 0件・date 0件 | `scatter` | なし | xAxis=number[0], yAxis=number[1] |
    | date ≥1件・number ≥1件（string の有無問わず） | `line` | date[0] | number[0] / sum |
    | string ≥1件・number ≥1件・date 0件 | `bar` | string[0] | number[0] / sum |
    | 上記すべてに該当しない | `table` | なし | なし |

  - [ ] 推薦根拠テキスト（`rationale`）が条件ごとに異なる内容になっている（例：「日付列と数値列が見つかったため折れ線グラフを推薦します」）

### FEAT-AR-002: `autoRecommend` テスト

- **優先度**: Must
- **説明**: `autoRecommend` の正常系・境界値を Vitest でカバーする。外部依存がないため実行環境を選ばない。
- **受け入れ基準**:
  - [ ] 列が0件のとき `chartType: "table"` が返る
  - [ ] 全列が string 型（number も date もなし）のとき `chartType: "table"` が返る
  - [ ] 全列が number 型（1件）のとき `chartType: "kpi"` が返り、measure に該当列が含まれる
  - [ ] number 列が2件以上、string/date なしのとき `chartType: "scatter"` が返り、xAxisColumn と yAxisColumn にそれぞれ1件目・2件目の number 列名が入る
  - [ ] date 列と number 列が混在するとき `chartType: "line"` が返り、groupByColumn と xAxisColumn に date 列が入る
  - [ ] string 列と number 列が混在し date がないとき `chartType: "bar"` が返り、groupByColumn と xAxisColumn に string 列が入る
  - [ ] 列数が多い（10列超）ケースでも結果が変わらず先頭優先ルールが守られる
  - [ ] 同一入力に対してテストを2回呼び出しても同じ結果が返る（冪等性）

### FEAT-AR-003: ダイアログでの列型情報保持

- **優先度**: Must
- **説明**: `WidgetEditDialog` がデータソース選択後に取得した列情報を、現状の列名文字列配列ではなく型情報付きの形式（name + inferredType）で保持するよう変更する。これにより `autoRecommend` が型を参照できるようになる。
- **受け入れ基準**:
  - [ ] データソースを選択したとき、列の名前だけでなく各列の型（number / date / string）が内部状態として保持されている
  - [ ] 型情報付きの列情報をグルーピング列・集計列・軸列の各プルダウンに渡しても、プルダウンの表示項目（列名）・動作・選択肢の数が変化しない（既存 UX への影響なし）
  - [ ] データソースを変更すると列型情報がリセット（前のデータソースの型情報が残らない）される
  - [ ] データソースの取得に失敗したとき、型情報は空として扱われ画面がエラーにならない

### FEAT-AR-004: 推薦適用ボタン

- **優先度**: Must
- **説明**: `WidgetEditDialog` でデータソースを選択し列情報が取得されたあと、「おすすめ設定を適用」ボタンが表示される。ボタンを押すと推薦結果がフォームの各フィールド（チャート種別・グルーピング列・集計列・X軸列・Y軸列）に一括セットされる。
- **受け入れ基準**:
  - [ ] データソースを選択し列情報の取得が完了すると「おすすめ設定を適用」ボタンが表示される
  - [ ] 列情報がまだ取得中のときボタンは表示されない（または無効化されている）
  - [ ] データソースが未選択のときボタンは表示されない
  - [ ] ボタンを押すと、推薦結果のチャート種別・グルーピング列・集計列（列名と集計関数）・X軸列・Y軸列がフォームにセットされ、ライブプレビューに即時反映される
  - [ ] ボタンを押さずにフォームを手動で設定・保存しても既存の動作に変化がない（推薦は強制されない）
  - [ ] 推薦結果が `table` のときもボタンは表示され、押すとチャート種別が `table` にセットされる
  - [ ] ボタンを複数回押してもフォームが同じ状態になる（冪等）

---

### FEAT-AR-005: 推薦根拠テキスト表示

- **優先度**: Should
- **説明**: 「おすすめ設定を適用」ボタンの近傍に、推薦根拠（なぜそのチャート種別を選んだか）を1行で表示する。ユーザーが推薦の意図を理解でき、採用・拒否の判断を立てやすくなる。
- **受け入れ基準**:
  - [ ] ボタンが表示されているとき、その直近に推薦根拠テキストが1行で表示される
  - [ ] 根拠テキストはチャート種別ごとに内容が異なり、選択されたチャートに対応する理由が書かれている
  - [ ] テキストが長すぎてレイアウトを崩さないよう、折り返し・省略などの対策がされている

---

### FEAT-AR-006: 既存設定がある場合の確認

- **優先度**: Could
- **説明**: すでにチャート種別・グルーピング列・集計列・軸列のいずれかが設定されている状態で「おすすめ設定を適用」を押したとき、上書きを促す確認をインライン（アラートダイアログ不使用）で行う。
- **受け入れ基準**:
  - [ ] フォームが初期状態（何も設定されていない）のときはボタンを押すと即座に推薦が適用される
  - [ ] フォームに既存設定があるとき、ボタンを押すと「現在の設定を上書きしますか？（はい / キャンセル）」相当のインライン確認が表示される
  - [ ] 「はい」を選ぶと推薦設定で上書きされる
  - [ ] 「キャンセル」を選ぶと既存の設定が維持される

## UX フロー

1. ユーザーがダッシュボード編集画面でウィジェットの設定アイコンをクリックし、`WidgetEditDialog` を開く
2. データソースのプルダウンからデータソースを選択する
3. ダイアログがバックグラウンドでデータソースの列情報（名前と型）を取得する
4. 取得完了後、「おすすめ設定を適用」ボタンと推薦根拠テキスト（例：「日付列と数値列が見つかったため折れ線グラフを推薦します」）が表示される
5. ユーザーがボタンを押すと、チャート種別・グルーピング列・集計列・軸列が自動でセットされ、右側のライブプレビューが即座に更新される
6. ユーザーは推薦された設定を確認し、必要に応じて手動で微調整する（またはそのまま保存する）
7. ユーザーが推薦を使わない場合は、ボタンを無視して従来どおり手動で各フィールドを設定できる

## 非機能要件

- **信頼性**: `autoRecommend` は例外を投げず、どのような入力に対しても有効な推薦結果オブジェクトを返す。列情報の取得失敗時はフォールバックとして `table` を返す
- **セキュリティ**: 推薦ロジックはクライアント側の純粋関数であり、新たなサーバー呼び出し・認証情報の取り扱いは発生しない
- **パフォーマンス**: `autoRecommend` の実行時間は列数に比例するが、通常の列数（〜100列）では体感遅延が生じない（1ms 以内で完了する）。列情報の取得は既存の `useEffect` フロー（`/api/datasources/:id`）を流用し、追加のネットワーク往復は発生しない
