# Kan. Sheets BI 仕様書

## 概要
Kan. Sheets BI は、Google スプレッドシートのデータを取り込み、多彩なグラフで可視化し、ドラッグ&ドロップで自由にレイアウトできるダッシュボードを構築・PDF出力できる、認証付きの Web アプリケーションである。スプレッドシートでデータを管理しているが可視化・共有資料作成に手間がかかっている個人・チームの担当者を主な対象とする。データソースはユーザー直下のトップレベル資産として登録し、複数のダッシュボードから繰り返し再利用できる点が特徴。v1 は所有者スコープ（他ユーザーとの共有なし）とし、ログインしたユーザーが自分のシートと自分のダッシュボードだけを管理する世界に閉じる。最終的にユーザーは「シートを登録する → グラフを並べる → 配置を整える → PDFで配布する」という一連の流れを迷いなく完了できることを目指す。

## 機能一覧

### FEAT-001: Google アカウント認証
- **優先度**: Must
- **説明**: Google アカウントでログイン・ログアウトできる。未ログイン状態では保護された画面・機能に一切アクセスできない。
- **受け入れ基準**:
  - [ ] 未ログインで保護された画面にアクセスするとログイン画面へ誘導される
  - [ ] Google アカウントでログインすると自分のダッシュボード一覧画面に到達する
  - [ ] ログアウトすると保護された画面に再びアクセスできなくなる
  - [ ] ログインの成功・失敗が記録として残る

### FEAT-002: データソース登録（スプレッドシート連携の基本）
- **優先度**: Must
- **説明**: ユーザーは Google スプレッドシートの URL と読み込み範囲を指定して、自分専用の「データソース」をトップレベル資産として登録できる。登録時に取得内容のプレビューを確認できる。
- **受け入れ基準**:
  - [ ] スプレッドシートの URL を入力すると対象シートが特定され、名前・読み込み範囲を指定して登録できる
  - [ ] 登録前に先頭数行のプレビューと、各列の名称・推定された型を確認できる
  - [ ] 自分が閲覧権限を持つプライベートなシートを登録・取得できる
  - [ ] 一般公開されているシートも登録・取得できる
  - [ ] 取得や読み込みに失敗した場合、原因が分かる形でエラーが表示される

### FEAT-003: データソースの再利用と一覧管理
- **優先度**: Must
- **説明**: 登録済みのデータソースは一覧表示・編集・削除でき、複数のダッシュボードのウィジェットから繰り返し参照できる。ダッシュボードを削除してもデータソースは消えない。
- **受け入れ基準**:
  - [ ] データソース一覧で名称・接続元シート・更新間隔・状態を確認できる
  - [ ] 1つのデータソースを複数のダッシュボードのウィジェットから利用できる
  - [ ] あるダッシュボードを削除しても、参照していたデータソース自体は一覧に残る
  - [ ] 何らかのウィジェットが使用中のデータソースは直接削除できず、その旨が示される
  - [ ] 使用されていないデータソースは削除でき、一覧から消える

### FEAT-004: 列の型定義と手動オーバーライド
- **優先度**: Must
- **説明**: 取得した列はシステムが型（数値・日付・文字列）を自動推定するが、ロケールや表記揺れにより誤判定が起こり得るため、ユーザーが手動で型を上書き指定できる。
- **受け入れ基準**:
  - [ ] 各列に推定された型がプレビューで表示される
  - [ ] 任意の列について型を手動で変更し、保存できる
  - [ ] 上書きした型がデータの表示・グラフ描画・集計に反映される
  - [ ] 上書き内容は再読込後も保持される

### FEAT-005: スプレッドシートデータの更新と再取得
- **優先度**: Must
- **説明**: 取得済みのデータは一定間隔で自動更新されるほか、ユーザーが手動で「今すぐ更新」を指示できる。再取得が短時間に連打されないよう制御される。
- **受け入れ基準**:
  - [ ] データソースに更新間隔を設定でき、設定どおりに自動的にデータが更新される
  - [ ] 「今すぐ更新」を実行すると最新のシート内容が反映される
  - [ ] 短時間に連続して更新を要求すると制限がかかり、その旨が分かる
  - [ ] 同時に複数の利用者・画面から同じデータへアクセスしても、元のシートへの問い合わせが過剰に発生しない

### FEAT-006: アクセス権の自動維持（再認可導線）
- **優先度**: Must
- **説明**: ユーザーがログインしてからしばらく経っても、システムが裏側でアクセス権を自動的に保ち、本人が不在のタイミング（自動更新・PDF生成など）でもシートを取得できる。アクセス権が失効した場合は再度許可を求める導線を表示する。
- **受け入れ基準**:
  - [ ] ログインから時間が経過したあとでも、自動更新やPDF出力でシートのデータが取得できる
  - [ ] Google 側でアクセス許可が取り消された場合、該当のデータソースが「再認可が必要」状態として表示される
  - [ ] 「再認可が必要」状態のデータソースに対し、再度許可を与える導線から復旧できる
  - [ ] アクセス権の問題でバックグラウンド更新が黙って失敗することがない

### FEAT-007: ダッシュボードの作成・一覧・複製・削除
- **優先度**: Must
- **説明**: ユーザーはログイン後、自分のダッシュボード一覧を確認し、新規作成・複製・削除ができる。各カードにはタイトル・説明・更新日時が表示される。
- **受け入れ基準**:
  - [ ] ログイン後にダッシュボード一覧（タイトル・説明・更新日時を持つカード形式）が表示される
  - [ ] 新規作成すると空のダッシュボードが作られ、編集画面に進める
  - [ ] 既存のダッシュボードを複製でき、複製後は元と独立して編集できる
  - [ ] ダッシュボードを削除でき、一覧から消える
  - [ ] 自分以外のユーザーのダッシュボードは一覧にも詳細にも表示されない

### FEAT-008: グラフウィジェットの追加・設定
- **優先度**: Must
- **説明**: ユーザーはダッシュボード上にグラフ（ウィジェット）を追加し、参照するデータソース・集計方法（グルーピング・集計値・絞り込み・並び替え）・見た目（軸割当、配色、凡例表示など）を設定できる。
- **受け入れ基準**:
  - [ ] ウィジェットを追加し、参照するデータソースを選択できる
  - [ ] グルーピング・集計方法・絞り込み条件・並び替え・件数上限を設定し、結果に反映される
  - [ ] 軸への割当、配色、凡例・ラベルの表示有無などの見た目を設定できる
  - [ ] 設定変更はその場でプレビューに反映される
  - [ ] 設定内容は保存され、再読込・再訪問後も保持される

### FEAT-009: 多彩なグラフ種別での可視化
- **優先度**: Must
- **説明**: 折れ線・棒（縦/横/積み上げ）・面・円/ドーナツ・散布図・バブル・レーダー・ヒートマップ・ゲージ・ツリーマップ・ファネル・KPIカードなど、目的に応じた多様なグラフ種別から選んで描画できる。
- **受け入れ基準**:
  - [ ] 最低5種類以上のグラフ種別から選んで描画できる
  - [ ] 同じデータソース・集計設定のまま、グラフ種別を切り替えられる
  - [ ] 各グラフは画面サイズに応じて見やすく表示される
  - [ ] 数値・カテゴリ・日付など異なる性質のデータを扱うグラフでも正しく描画される

### FEAT-010: グラフのアクセシビリティ対応（データテーブル併設）
- **優先度**: Must
- **説明**: 視覚的なグラフだけでなく、同じデータを表形式でも確認できるようにし、スクリーンリーダー利用者やコピー用途、PDF収録時にも情報が欠落しないようにする。
- **受け入れ基準**:
  - [ ] 各グラフに対応するデータテーブルを表示・切替できる
  - [ ] スクリーンリーダーでグラフの内容（種別・主要な値）を認識できる
  - [ ] データテーブルの内容をコピーまたはエクスポートできる
  - [ ] PDF出力したときにもグラフとあわせて内容を確認できる形で収録される

### FEAT-011: 自由レイアウト編集（ドラッグ&ドロップ配置）
- **優先度**: Must
- **説明**: ユーザーはダッシュボード編集画面でウィジェットを自由にドラッグ移動・リサイズして配置でき、その配置は保存され再訪問時にも維持される。編集モードと閲覧モードを切り替えられる。
- **受け入れ基準**:
  - [ ] 編集モードでウィジェットをドラッグして自由に移動できる
  - [ ] ウィジェットの大きさを変更（リサイズ）できる
  - [ ] 配置は保存され、再読込・再訪問後も同じ配置で表示される
  - [ ] 閲覧モードでは配置の変更ができず、内容の確認に専念できる
  - [ ] 画面幅（PC/タブレットなど）に応じて適切なレイアウトで表示される

### FEAT-012: ウィジェット削除時のレイアウト整合性維持
- **優先度**: Must
- **説明**: ウィジェットを削除すると、そのウィジェットが占めていたレイアウト上の領域も同時に整理され、空白や孤立した配置情報が残らないようにする。
- **受け入れ基準**:
  - [ ] ウィジェットを削除すると、対応するレイアウト上の配置情報も同時に消える
  - [ ] 削除後に再読込しても、存在しないウィジェットの配置情報が残らない
  - [ ] 新しいウィジェットを追加すると、レイアウト上の空いている位置に自動的に配置される

### FEAT-013: ダッシュボードのPDF出力
- **優先度**: Must
- **説明**: ユーザーは現在のダッシュボードをPDFとして出力できる。グラフを含む内容が画面表示に近い見た目で再現され、用紙サイズ・向きを選べる。出力には名称と生成日時が含まれる。
- **受け入れ基準**:
  - [ ] ダッシュボード画面からPDF出力を実行し、ファイルとして取得できる
  - [ ] 出力されたPDFにすべてのグラフが正しく描画され、欠けや途中状態のまま出力されることがない
  - [ ] 用紙サイズ（A4/A3）と向き（縦/横）を選択して出力できる
  - [ ] 出力されたPDFにダッシュボード名と生成日時が含まれる
  - [ ] PDF出力用のアクセス情報は使い回しできず、短時間で無効になる

### FEAT-014: アクセス制御と他者リソースの保護
- **優先度**: Must
- **説明**: すべての操作・閲覧においてログイン状態と所有権が確認され、他のユーザーのダッシュボードやデータソースには一切アクセスできないようにする。
- **受け入れ基準**:
  - [ ] 他のユーザーが所有するダッシュボード・データソースへの直接アクセスは拒否される
  - [ ] 未ログイン状態での操作はすべてログイン画面へ誘導される
  - [ ] 拒否された操作には分かりやすいメッセージが表示される
  - [ ] 重要な操作（ログイン、エクスポートなど）の記録が残り、後から確認できる

### FEAT-015: アカウント・データソース削除のポリシー
- **優先度**: Should
- **説明**: ユーザーは自分のアカウントを削除でき、その際にダッシュボード・ウィジェット・データソースが矛盾なく整理される。使用中のデータソースの削除制限とあわせて、安全な削除体験を提供する。
- **受け入れ基準**:
  - [ ] アカウント削除を実行すると、自分が所有するダッシュボード・ウィジェット・データソースがすべて整理され、エラーで中断しない
  - [ ] 削除確認の前に、削除される内容が分かるように説明が表示される
  - [ ] 削除は取り消せないことが明示される

### FEAT-016: 多言語表示への対応
- **優先度**: Should
- **説明**: 画面の文言は言語切替の仕組みに対応しており、初期は日本語で提供しつつ、将来的に他言語へ拡張できる。
- **受け入れ基準**:
  - [ ] アプリ全体が日本語で一貫して表示される
  - [ ] 画面文言が言語ごとに切り替えられる構造になっている（追加言語の有効化で表示が切り替わる）
  - [ ] 数値・日付などの表示形式が表示言語/地域に応じて崩れない

### FEAT-017: 複数データソースの結合利用（将来拡張）
- **優先度**: Could
- **説明**: 1つのウィジェットで複数のデータソースを組み合わせて可視化できるようにする。
- **受け入れ基準**:
  - [ ] 複数のデータソースを選択してひとつのグラフに反映できる
  - [ ] 結合条件（キー列の対応など）を設定できる

### FEAT-018: ダッシュボードの共有・公開リンク（将来拡張）
- **優先度**: Could
- **説明**: 所有者以外のユーザーや外部の閲覧者とダッシュボードを共有できるようにする（v1の所有者スコープを超える拡張）。
- **受け入れ基準**:
  - [ ] 特定の相手にダッシュボードの閲覧権限を付与できる
  - [ ] 外部向けの公開リンクを発行・無効化できる

### FEAT-019: 定期PDF配信（将来拡張）
- **優先度**: Could
- **説明**: ダッシュボードのPDFをスケジュールに従って自動生成し、メールなどで定期配信する。
- **受け入れ基準**:
  - [ ] 配信スケジュール（頻度・宛先）を設定できる
  - [ ] 設定した周期で自動的にPDFが生成・配信される

## UXフロー
1. ユーザーはトップページから Google アカウントでログインする。初回ログイン後、空のダッシュボード一覧画面が表示される。
2. 「データソースを登録」からスプレッドシートのURLと範囲を入力し、プレビューで列名・型を確認、必要に応じて型を上書きして登録する。
3. ダッシュボード一覧で「新規作成」を選び、空のダッシュボードの編集画面に入る。
4. 編集画面でウィジェットを追加し、登録済みのデータソースを選択、グルーピング・集計・絞り込みを設定し、グラフ種別と見た目を選んでプレビューを確認しながら調整する。
5. 必要なグラフを追加したら、編集モードでウィジェットをドラッグ&ドロップして配置・サイズ調整し、見やすいレイアウトに整える。
6. 閲覧モードに切り替えて、最終的な見た目を確認する。データの数値が気になる箇所は、グラフに併設されたデータテーブルで詳細を確認する。
7. データを最新化したい場合は「今すぐ更新」を押し、シートの最新内容が反映されたことを確認する。
8. 共有・配布が必要なときは「PDF出力」を選び、用紙サイズと向きを指定して、グラフを含む資料としてPDFを取得する。
9. 別のテーマのダッシュボードを作る際は、既存のデータソースを再利用しながら新しいダッシュボードを作成する。不要になったダッシュボードは複製・削除で整理する。
10. データソースへのアクセス権に問題が生じた場合は、ダッシュボードまたはデータソース管理画面で「再認可が必要」の表示を確認し、案内に従って許可をやり直す。

## 非機能要件
- **信頼性**: データ取得・集計・PDF生成のいずれにおいても、失敗時にはユーザーに原因が分かる形でフィードバックされ、システムが不整合な状態（孤立したレイアウト項目、消えないキャッシュ、宙に浮いた参照など）に陥らないこと。アクセス権の失効など外部要因による失敗も静かに無視されず、復旧導線が示されること。
- **セキュリティ**: ログイン状態と所有権の確認なしにいかなるリソースにもアクセスできないこと。スプレッドシートへのアクセスや認証情報の取り扱いはすべてサーバー側で完結し、利用者のブラウザに機微な情報が渡らないこと。PDF出力用のアクセス情報は一度きり・短命であること。重要な操作（認証・出力）が記録として残ること。
- **パフォーマンス**: キャッシュが効いている状態でダッシュボードが速やかに表示されること。大量データを扱うデータソースでも、必要な範囲に絞った取得とサーバー側での集計により、画面表示や出力が実用的な速度で完了すること。同時アクセスが集中しても外部のスプレッドシートへの問い合わせ回数が抑制されること。
- **アクセシビリティ・国際化**: グラフは視覚情報だけに依存せず、データテーブルの併設やスクリーンリーダー対応によって内容を確認できること。表示言語は切り替え可能な構造を持ち、初期は日本語で違和感なく利用できること。
