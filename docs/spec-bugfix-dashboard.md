# ダッシュボードバグ修正 仕様書

## 概要

ダッシュボード画面およびPDF出力機能で確認された4件のバグを修正する。
対象ユーザーはログイン済みの所有者スコープユーザー。
バグはいずれも既存の実装ロジックの不備に起因しており、新機能の追加ではなく現状仕様の正常動作への復旧が目的である。
スプリントはデータ取得フローを先に修正し、その結果を画面で確認できる順番に組んである。

---

## 機能一覧

### FEAT-BF-001: `/dashboards/*/print` をミドルウェア認証ガードから除外する

- **優先度**: Must
- **説明**: 印刷ページ（`/dashboards/:id/print`）は現在 `PROTECTED_PREFIXES` の `/dashboards` に前方一致するため、Auth.js セッション Cookie を持たない Playwright がアクセスするとミドルウェアがログインページへリダイレクトする。このページは独自の PDF トークン認証（`x-pdf-token` ヘッダー）を持つため、セッション Cookie による認証は不要であり、ミドルウェアの対象から除外する必要がある。
- **受け入れ基準**:
  - [ ] `/dashboards/any-id/print` へのリクエストが、`x-pdf-token` ヘッダーを付けなくてもミドルウェアによって `/login` にリダイレクトされない
  - [ ] `/dashboards/any-id/print` ではない通常の `/dashboards` 配下のパスは、従来どおり未ログイン時に `/login` へリダイレクトされる
  - [ ] `isProtectedPath` のユニットテストに印刷パスの除外ケースが追加されている

### FEAT-BF-002: ECharts 描画完了シグナルと Playwright 待機の改善

- **優先度**: Must
- **説明**: `playwrightPdf.ts` は現在 `waitForSelector("svg")` と固定 1500ms 待機でグラフ描画完了を判定している。仕様書 §5 FR-5（3-3対応）では ECharts の `finished` イベントで `window.__chartsReady` フラグを立て、Playwright が `waitForFunction` で待機する方式を定めている。また印刷モードで ECharts のアニメーションを `animation: false` にしないと `finished` 発火が不安定になる。
- **受け入れ基準**:
  - [ ] 印刷ページ（`/dashboards/:id/print`）のクライアントコードで、全 ECharts インスタンスが `finished` イベントを発火した後に `window.__chartsReady = true` がセットされる
  - [ ] Playwright のページ取得処理が `waitForFunction(() => window.__chartsReady, { timeout: 15000 })` でグラフ描画を待機する（固定 1500ms 待機を廃止）
  - [ ] 印刷ページ（`/print` ルート）でレンダリングされる全 ECharts インスタンスが `animation: false` で初期化される
  - [ ] グラフがないダッシュボードを印刷した場合も、`__chartsReady` フラグが適切にセットされ PDF 生成が完了する

### FEAT-BF-003: データ取得失敗状態をウィジェットカードで区別して表示する

- **優先度**: Must
- **説明**: ダッシュボード詳細ページおよび印刷ページでは、データソースからのデータ取得失敗を `catch { queryResult = null }` で握り潰し、「データソース未設定」と同一の表示にしている。REAUTH_REQUIRED（OAuth スコープ不足・リフレッシュトークン失効）、FORBIDDEN、NETWORK_ERROR 等の取得失敗をユーザーが認識できるよう、エラー状態を画面に表示する必要がある。
- **受け入れ基準**:
  - [ ] ウィジェットにデータソースが設定されているが取得に失敗した場合、ウィジェットカードに「データの取得に失敗しました」に相当するエラー表示がされる（データソース未設定の表示とは見た目で区別できる）
  - [ ] REAUTH_REQUIRED エラーの場合は「アクセス権の再認可が必要です」に相当するメッセージとデータソース設定ページへの導線が表示される
  - [ ] データ取得失敗が発生してもページ全体のクラッシュは起こらず、他のウィジェットは正常表示される
  - [ ] ダッシュボードページのサーバーコンポーネントが、エラーコードを区別した状態（`{ status: "error"; code: string }` 相当）をクライアントに渡せる

### FEAT-BF-004: AddWidgetDialog の成功後状態を再開放時にリセットする

- **優先度**: Must
- **説明**: `AddWidgetDialog` 内の `useActionState` は成功状態（`status: "success"`）が次回ダイアログ開放時も残る。`DashboardDetailClient` でインライン定義された `onClose` 関数は再レンダリングのたびに新しい参照になるため、再開放時に `useEffect([state.status, onClose])` が発火し `onClose()` が即時呼ばれてダイアログが瞬時に閉じる。2回目以降のウィジェット追加ができなくなる。
- **受け入れ基準**:
  - [ ] 1回目のウィジェット追加が完了してダイアログを閉じた後、「ウィジェットを追加」ボタンをクリックするとダイアログが開き、空のフォームが表示される
  - [ ] 2回目以降のウィジェット追加操作でも、正常にウィジェットが作成されダッシュボードに追加される
  - [ ] ダイアログを閉じた直後に再度開いても、前回の成功メッセージやエラーメッセージが残っていない

### FEAT-BF-005: ChartWidget の高さをグリッドアイテムの実際のサイズに追従させる

- **優先度**: Must
- **説明**: `WidgetCard` は `ChartWidget` に固定値 `height={180}` を渡している。`DashboardGrid` の `rowHeight=80`・デフォルト `h=4` でグリッドアイテムは約 320px になるが、チャート描画高さは 180px に固定されコンテンツが見切れる。`ChartWidget` が親コンテナの高さを自動的に埋めるように変更し、ウィジェットをリサイズしても描画が追従する必要がある。
- **受け入れ基準**:
  - [ ] ウィジェットカードを編集モードでリサイズしたとき、チャート（ReactECharts）がカードの内容領域の高さに追従して再描画される
  - [ ] 初期表示（`h=4`）でチャート全体がウィジェットカード内に収まり、見切れが発生しない
  - [ ] ウィジェットをリサイズしてページをリロードしても、保存されたサイズでチャートが正しく描画される
  - [ ] KPI カード・テーブル種別のウィジェットでも見切れが発生しない

### FEAT-BF-006: ウィジェットの最小サイズを保証する

- **優先度**: Should
- **説明**: リサイズ可能になった場合、ウィジェットをヘッダーや操作ボタンが見切れる程度まで縮小できてしまう。レイアウトアイテムに `minW` / `minH` を設定し、コンテンツが最低限読めるサイズを下回れないようにする。
- **受け入れ基準**:
  - [ ] ウィジェットを縮小しようとしたとき、`minW=3`（グリッドコラム数）、`minH=3`（rowHeight 換算）以上の大きさを下回れない
  - [ ] 既存ウィジェットのレイアウトデータに `minW`/`minH` が付与されても正常に描画される

### FEAT-BF-007: データ取得失敗時の Sentry / 構造化ログへの記録

- **優先度**: Should
- **説明**: 現在のサイレントキャッチでは取得失敗の発生頻度や原因を把握できない。仕様書 §6 の観測性要件に従い、ダッシュボードページでのデータ取得失敗を構造化ログ（`console.error` + Sentry）に記録する。ユーザー体験には影響しないが運用上必要。
- **受け入れ基準**:
  - [ ] ダッシュボードページでデータ取得が失敗した場合、エラーコード・`dataSourceId`・`widgetId` を含む構造化ログが出力される
  - [ ] Sentry にエラーレポートが送信される

### FEAT-BF-008: PDF 生成エラーのユーザー向けフィードバック改善

- **優先度**: Could
- **説明**: 現在 PDF 生成失敗（Playwright クラッシュ・ネットワークエラー等）時に HTTP 500 が返るだけで、ユーザー向けには `PdfDownloadButton` の汎用エラーメッセージが表示される。エラー種別（認証切れ・ダッシュボード空等）を区別したメッセージにすることで、ユーザーが次の行動を取りやすくなる。
- **受け入れ基準**:
  - [ ] PDF 生成に失敗したとき、ユーザーにエラーの概要（「PDF の生成に失敗しました。再試行するか、しばらく経ってからお試しください。」相当）が表示される
  - [ ] ウィジェットが一件もないダッシュボードで PDF 出力ボタンを押した場合、生成前に警告メッセージが表示される

## UXフロー

### PDF 出力（修正後）

1. ユーザーがダッシュボード詳細ページで「PDF 出力」ボタンをクリックする
2. フロントエンドが `GET /api/dashboards/:id/pdf` をリクエストする
3. サーバーがユーザーセッションを確認し、PDF トークンを発行する
4. Playwright がヘッダーにトークンを付与して `/dashboards/:id/print` にアクセスする
5. ミドルウェアはこのパスを保護対象から除外しているため、ページコンポーネントが起動する
6. 印刷ページがトークンを検証してダッシュボードデータを取得しグラフを描画する
7. 全 ECharts インスタンスが `finished` を発火した後 `window.__chartsReady = true` がセットされる
8. Playwright が `waitForFunction` でフラグを検知し PDF をキャプチャする
9. PDF ファイルがダウンロードされる

### ウィジェット連続追加（修正後）

1. ユーザーが「ウィジェットを追加」ボタンをクリックする（1回目）
2. 空のフォームが表示され、チャート種別・タイトル・データソースを入力する
3. 「追加」ボタンをクリックするとウィジェットが作成されダイアログが閉じる
4. ユーザーが再度「ウィジェットを追加」ボタンをクリックする（2回目）
5. 前回の状態がリセットされた空のフォームが表示される
6. 追加操作が正常に完了する

### データ取得失敗の通知（修正後）

1. ダッシュボード詳細ページを開く
2. データ取得に失敗したウィジェットがある場合、該当ウィジェットカードにエラー状態が表示される
3. REAUTH_REQUIRED の場合は「アクセス権の再認可が必要です」とデータソース設定ページへのリンクが表示される
4. 他のウィジェットは正常にグラフが表示されている

### ウィジェットリサイズ（修正後）

1. 編集モードに切り替える
2. ウィジェットの右下のリサイズハンドルをドラッグして縦横に拡大する
3. ドラッグ中・完了後にチャートの描画高さがリアルタイムで追従する
4. 最小サイズ（`minW=3`, `minH=3`）以下には縮小できない

## 非機能要件

- **信頼性**: データ取得失敗は個別ウィジェット単位でハンドリングし、ページ全体のクラッシュを防ぐ。PDF トークンは単回使用・有効期限（5分）を維持する。
- **セキュリティ**: 印刷ページをミドルウェアの対象外にしても、ページコンポーネント内の PDF トークン検証（`consumePdfToken`）は変更しない。トークン不正・期限切れ・バインディング不一致は引き続き 404 で返す。`PROTECTED_PREFIXES` の変更は最小限（print パスの除外のみ）とし、他パスへの影響がないことをテストで確認する。
- **パフォーマンス**: `window.__chartsReady` の `waitForFunction` タイムアウトは 15 秒を維持する。固定 1500ms 待機の廃止により PDF 生成の所要時間が改善することを期待する。
- **観測性**: データ取得失敗を構造化ログ・Sentry に記録することで、本番環境での問題発生頻度をモニタリングできるようにする。
